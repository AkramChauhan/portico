How these docs stay honest

Shared facts live in one file

Capabilities, assumptions, risks and the glossary come from docs/data/data.js. Documents render from it rather than restating it, so the same fact cannot drift into four subtly different versions.

Every doc declares what it describes

A doc:sources meta tag lists the code paths it documents, alongside a doc:reviewed date. That is what makes staleness detectable rather than a matter of memory.

A checker, not a good intention

node docs/check-freshness.mjs compares each reviewed date against the last change to the code it claims to describe, and exits non-zero when behind.

Unverified claims are labelled

Anything not actually tested is registered as an assumption with a stated way to kill it. If a number is not in that register, it was verified.
